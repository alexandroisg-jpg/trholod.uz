# TR HOLOD — trholod.uz

Исходники магазина в аккаунте владельца: https://github.com/alexandroisg-jpg/trholod.uz.

Эта версия подготовлена для самостоятельного размещения в **Cloudflare Workers + D1 в аккаунте владельца**. GitHub хранит исходники; Cloudflare выполняет сайт и хранит заказы; `trholod.uz` служит адресом магазина. GitHub Pages не подходит для серверных заказов и управления базой.

**Статус на 22.09.2026:** сайт работает на `https://trholod.uz` в аккаунте владельца Cloudflare, с собственной базой D1 и защищённым входом. Зона активна; HTTP и `www.trholod.uz` перенаправляются на основной HTTPS-адрес с сохранением пути и параметров. На основном домене проверены все 73 публичные страницы, метаданные, 65 блоков Product JSON-LD, 45 уникальных изображений и защита закрытых разделов. Ранее в браузере проверены вход, управление, выход, вид на телефоне и компьютере; создание, повтор и отмена заказа проверены в собственной D1. **73 адреса отправлены в IndexNow 22.09.2026 в 13:27 UTC: ответ HTTP 202**, уведомление принято, проверка ключа ожидается. Фактическая индексация не подтверждена. Google Search Console и автоматическая публикация GitHub Builds пока не подключены.

## Что находится в проекте

- 66 активных демонстрационных товаров: 8 позиций хладагентов (7 марок газа), 36 компрессоров, 14 комплектующих и 8 инструментов VALUE.
- Поиск, категории, фильтры, карточки с увеличением фотографий, корзина и оформление доставки/самовывоза.
- Заказы и остатки в D1; сервер проверяет цену, остаток и повтор запроса. При изменении цены нужна повторная проверка корзины.
- Личный список заказов и управление товарами, ценами, остатками и статусами заказов.
- Открытый каталог и страницы товаров доступны посетителям и поисковым роботам. Заказы и управление закрыты собственным входом владельца на `/login`; в админке тот же ключ нужно повторно ввести для подтверждения управления.
- Платежи, отправка уведомлений и 1С пока не подключены. Все цены и остатки остаются демонстрационными.

Существующие заказы с прежнего хостинга **не входят** в репозиторий и автоматически не переносятся. Новая D1 запускается с чистой базой и демонстрационным каталогом. Для переноса истории требуется отдельный экспорт из прежней базы и проверка сопоставления пользователей.

## Публикация и подключение домена

Конфигурация аккаунта и базы уже заполнена в `wrangler.json`. Для обновления этой установки не нужно заново создавать D1. С компьютера, авторизованного в аккаунте владельца:

```sh
npm ci
npx wrangler login
npm run check
npm run test:auth
npm run test:indexnow
node tests/refrigerant-packaging.test.mjs
npm run deploy
```

Команда собирает Worker, проверяет настройки и наличие обязательных runtime-секретов, применяет миграции к собственной D1 и загружает Worker с изображениями. Проверка секретов читает только их имена, а не значения. Учётная запись ChatGPT для работы сайта не требуется. Вход владельца реализован самим приложением; Cloudflare Zero Trust и Access для этой версии не нужны.

Домены уже привязаны к Worker через Cloudflare API. В `wrangler.json` сохранены маршруты для последующих публикаций:

```json
"routes": [
  { "pattern": "trholod.uz", "custom_domain": true },
  { "pattern": "www.trholod.uz", "custom_domain": true }
]
```

Основной домен работает. Дополнительный адрес владельца `https://trholod-uz.alexandro-isg.workers.dev` сохранён через `workers_dev: true`, а адреса отдельных версий отключены через `preview_urls: false`. Канонические адреса страниц указывают на `https://trholod.uz`. При необходимости дополнительный адрес можно отключить, установив `workers_dev: false` и опубликовав обновление. Настройки `assets` обеспечивают открытую загрузку изображений и стилей. Старые A/TXT для ChatGPT Sites к этой установке не относятся.

Проверить каталог и страницы товаров без входа, затем `/login`, «Мои заказы» и управление: создать тестовый заказ, изменить статус и отменить его с возвратом остатков. Без входа закрытые страницы должны перенаправлять на `/login`, а соответствующие API — отвечать 401. Ошибка настройки входа должна закрывать эти разделы с 503. Только после внешней проверки считать перенос завершённым.

`www.trholod.uz` также привязан к Worker. Приложение перенаправляет его на `https://trholod.uz` с кодом 308, сохраняя путь и параметры; HTTP на основном домене также переводится на HTTPS. Публичная проверка обоих адресов и перенаправлений прошла 22.09.2026. Основные SEO-адреса и sitemap используют только `https://trholod.uz`.

## Секреты и вход владельца

В Cloudflare уже заданы три runtime-секрета. Их значения не следует помещать в GitHub или переменные публичной сборки:

| Имя | Назначение |
| --- | --- |
| `ADMIN_ACCESS_KEY_SHA256` | SHA-256 случайного ключа владельца, 64 шестнадцатеричных символа в нижнем регистре. В форме входа и админке вводится исходный ключ, а не хеш. |
| `SESSION_SECRET` | Отдельное случайное значение длиной минимум 32 байта для подписи сеансов. |
| `OWNER_EMAIL` | Email владельца, который сервер записывает в сеанс; в форме вводится только ключ. |

Для смены конкретного секрета используется `npx wrangler secret put ИМЯ --config wrangler.json`; значение вводится в запросе Wrangler. Не передавайте его аргументом команды и не сохраняйте в отслеживаемых файлах. Ключ владельца должен быть длинным случайным значением. Смена ключа, секрета сеансов или email делает существующие сеансы недействительными. Для восстановления доступа владелец аккаунта Cloudflare может задать новый ключ и его хеш.

## Обновления из GitHub

После первого успешного размещения в своём Cloudflare открыть Worker `trholod-uz` → Settings → Builds и подключить этот репозиторий. Выбрать ветку `main`, корневой каталог `/`, Node.js `22.23.2` (файл `.nvmrc`), команду сборки `npm run build`, команду размещения `npm run deploy:built`. Токен сборки должен иметь права на Workers и D1 нужного аккаунта. Не добавлять токен в файлы репозитория. Другие ветки не публиковать в рабочий Worker автоматически.

Все три секрета задаются как runtime-secrets Worker. Секреты не нужно дублировать в общедоступных переменных сборки. На момент этой инструкции интеграция GitHub Builds ещё не подключена: новый push сам по себе не публикует сайт. Проверить настройки и пробную сборку после подключения.

## Локальная работа и проверки

Требуется Node.js 22.13+; проверено с 22.23.2.

```sh
npm ci
cp .dev.vars.example .dev.vars
```

Заполнить в локальном `.dev.vars` собственные тестовые `ADMIN_ACCESS_KEY_SHA256`, `SESSION_SECRET` и `OWNER_EMAIL` по описанию выше. Этот файл исключён из Git. Затем:

```sh
npm run db:migrate:local
npm run check
npm run test:auth
npm run test:indexnow
npm run build
npm run start
```

Каталог, SEO-страницы и изображения доступны без входа владельца. Для интерактивной проверки закрытых разделов открыть `/login` и ввести исходный тестовый ключ из локальной настройки. Скрытого обхода входа нет. `npm run test:auth` содержит 14 проверок подписанных сеансов, закрытых путей, отклонения поддельных заголовков, смены секретов, ограничений попыток входа, безопасных переходов, входа и выхода. Тесты используют временные ключи и отдельную SQLite в памяти, не рабочую D1.

`npm run dev` запускает Vite. Файлы `.dev.vars`, `.wrangler`, `node_modules`, `dist`, локальные базы и секреты исключены из Git. Три миграции схемы находятся в `drizzle/`; третья добавляет таблицу ограничений попыток входа. Новые изменения создавать через `npm run db:generate`, не изменять уже применённые миграции.

## Авторизация и заказы

После правильного ключа Worker создаёт подписанный сеанс HS256 на 8 часов в cookie `__Host-trholod-session` с `HttpOnly`, `Secure`, `SameSite=Lax`. Проверяются подпись, срок, issuer, audience, email и версия действующих секретов. Простые заголовки с email, старые заголовки Sites и заголовки Cloudflare Access не дают доступа. Закрыты `/admin`, `/orders`, `/api/admin`, `/api/orders` и вложенные пути. Главная, каталог, карточки товаров, `/credits`, `/api/catalog`, изображения, `robots.txt` и `sitemap.xml` публичны.

Вход и выход принимают JSON POST только со своего сайта. В D1 действует ограничение: до 10 попыток за 15 минут для одного IP с увеличивающейся задержкой и до 100 попыток за тот же период суммарно. Исходные IP в таблицу не записываются. Выход удаляет cookie на текущем устройстве.

Это один кабинет владельца, без регистрации покупателей: заказы относятся к стабильному внутреннему пользователю `owner-v1`. Админка дополнительно просит повторно ввести тот же ключ владельца; подтверждение хранится только в памяти страницы и сбрасывается при перезагрузке. Повтор заказа не создаёт дубль. Отмена возвращает остаток один раз. Цена ноль означает «Цена по запросу» и исключает оплату/заказ этой позиции.

## Фотографии и оставшиеся правки каталога

24.09.2026 по замечанию владельца удалены восемь файлов фотографий многоразовых баллонов R410A, R404A, R407C и R32. В карточках, корзине и управлении вместо них показан текст «Оригинальное фото готовится» с брендом и маркой газа. Увеличение и ссылки на эти фотографии отключены; изображение отсутствует в Product JSON-LD и Open Graph. Исходные файлы сохранены только в локальных рабочих материалах вне публичного сайта.

Добавлена подтверждённая малая фасовка R290 — 350 г из официального каталога Tura. Цена и наличие требуют уточнения: новая позиция создана с ценой по запросу и нулевым тестовым остатком. Вместе с R600a 420 г это две малые фасовки. 1 литр R600a содержит 0,42 кг; фасовки TR Gas именно 1 кг пока не подтверждены и не добавлялись.

Каталог теперь содержит 66 активных демонстрационных позиций и 74 публичные страницы в sitemap. Первая отправка IndexNow от 22.09.2026 охватывала прежние 73 адреса. Точечное обновление D1 сохраняет цены, остатки и пользовательские описания; собственное фото владельца не заменяется, новый товар вставляется только при отсутствии. Локально проверены все 74 публичные страницы, 43 пути изображений, вид на телефоне и компьютере; сборка и проверка типов прошли. Семь SQLite-тестов подтвердили сохранение данных при обновлении. В ESLint остаются 16 прежних ошибок правил ссылок и эффектов React; новых ошибок нет. Оригинальные фотографии одноразовой упаковки TR-GAS для четырёх позиций ещё нужны. R134a сохранён с подтверждённым фирменным фото. Фото R600a 420 г, R290 350 г и R290 5 кг — оригиналы из каталога Tura; логотип TR Gas на их лицевой стороне не виден.

Для ряда GMCC/Panasonic/Toshiba показаны фотографии близкой модели или серии; подписи это поясняют. Две позиции Panasonic используют одно фото серии. Нельзя считать все фотографии точными изображениями каждой модели. Цены ряда позиций — ориентиры по внешним магазинам, а не утверждённый владельцем прайс.

Источники, точность соответствия моделей и цены описаны в `lib/originals-provenance.json`, `lib/catalog-provenance.json` и на странице `/credits`. Сохранены водяные знаки и исходная атрибуция. Наличие фото в репозитории не означает передачу лицензии на него; права производителей и поставщиков сохраняются. Общая открытая лицензия на сторонние изображения не заявлена. Неиспользуемые прежние вымышленные изображения исключены из этого экспорта.

## Уведомление поисковых систем после публикации

**Первая отправка выполнена:** 22.09.2026 в 13:27 UTC сервис [IndexNow](https://www.indexnow.org/documentation) принял все 73 публичных адреса и ответил HTTP 202 (проверка ключа ещё ожидается). Повторять эту же отправку сейчас не требуется. Для уведомления после будущих изменений выполните `npm run indexnow:check`, затем `npm run indexnow:submit`. Скрипт читает действующий `sitemap.xml` (после обновления ожидаются 74 адреса), исключает закрытые разделы, API, посторонние домены и неканонические URL. Пока домен не работает, отправка останавливается. Публичный файл подтверждения — `public/fa7ea336dbe39a88a80b3a838bce7dd9.txt`; это не пароль и не доступ к хостингу. Регулярной отправки нет. Временная проверка запуска домена завершена; дальнейшие уведомления запускаются вручную после изменений.

Ответ IndexNow 200/202 означает получение уведомления сервисом, а не включение страниц в поиск. Уведомления распространяются между участвующими поисковиками, включая Bing; Google через IndexNow не уведомляется. Для Google в аккаунте с подтверждённым доступом к `trholod.uz` нужно вручную добавить `https://trholod.uz/sitemap.xml` в раздел Sitemaps [Google Search Console](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap#addsitemap). Сроки и факт индексации определяют поисковые системы; текущая индексация не подтверждена.
