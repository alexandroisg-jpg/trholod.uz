# TR HOLOD — trholod.uz

Исходники магазина в аккаунте владельца: https://github.com/alexandroisg-jpg/trholod.uz.

Эта версия подготовлена для самостоятельного размещения в **Cloudflare Workers + D1 в аккаунте владельца**. GitHub хранит исходники; Cloudflare выполняет сайт и хранит заказы; `trholod.uz` служит адресом магазина. GitHub Pages не подходит для серверных заказов и управления базой.

**Статус:** код подготовлен и проверен локально. Домен и собственная облачная база ещё не подключены. Значения аккаунта, базы и входа в `wrangler.json` намеренно не заполнены; команда публикации остановится до их настройки. Загрузка в GitHub сама по себе не переносит работающий сайт.

## Что находится в проекте

- 65 активных демонстрационных товаров: 7 хладагентов, 36 компрессоров, 14 комплектующих и 8 инструментов VALUE.
- Поиск, категории, фильтры, карточки с увеличением фотографий, корзина и оформление доставки/самовывоза.
- Заказы и остатки в D1; сервер проверяет цену, остаток и повтор запроса. При изменении цены нужна повторная проверка корзины.
- Личный список заказов и управление товарами, ценами, остатками и статусами заказов.
- Открытый каталог и страницы товаров доступны посетителям и поисковым роботам. Заказы и управление закрыты для владельца через Cloudflare Access; для админки дополнительно нужен отдельный ключ управляющего.
- Платежи, отправка уведомлений и 1С пока не подключены. Все цены и остатки остаются демонстрационными.

Существующие заказы с прежнего хостинга **не входят** в репозиторий и автоматически не переносятся. Новая D1 запускается с чистой базой и демонстрационным каталогом. Для переноса истории требуется отдельный экспорт из прежней базы и проверка сопоставления пользователей.

## Собственное размещение — порядок действий

1. В своём Cloudflare добавить зону `trholod.uz`. Cloudflare выдаст два NS-сервера. У регистратора домена заменить текущие NS на эту пару. Если используется доменная почта, заранее перенести её записи MX/TXT из панели прежнего DNS: автоматическое обнаружение сейчас может быть неполным. Старые A/TXT для ChatGPT Sites не использовать.
2. В Cloudflare Zero Trust создать **Access → Applications → Self-hosted** с четырьмя public hostname/path destinations в **одном приложении**: `trholod.uz/admin`, `trholod.uz/orders`, `trholod.uz/api/admin`, `trholod.uz/api/orders`. Эти пути защищают также вложенные адреса. Настроить вход по email и политику **Allow → Emails → адрес владельца**. Получить Team domain и единый Application Audience (AUD). Не включать защиту всего домена или всего Worker: главная, каталог, страницы товаров, изображения, `/api/catalog`, `robots.txt` и `sitemap.xml` должны открываться без входа. Сначала настроить защиту закрытых разделов, затем публиковать Worker.
3. Войти в Cloudflare и создать базу в том же аккаунте:

   ```sh
   npx wrangler login
   npx wrangler d1 create trholod-db
   ```

4. Заполнить `wrangler.json`: добавить `account_id` своего аккаунта, заменить `database_id` на ID созданной D1, заполнить `CLOUDFLARE_ACCESS_TEAM_DOMAIN` (например, `https://your-team.cloudflareaccess.com`), `CLOUDFLARE_ACCESS_AUD` и `OWNER_EMAIL`. Добавить маршрут:

   ```json
   "routes": [{ "pattern": "trholod.uz", "custom_domain": true }]
   ```

   Это идентификаторы и настройки, не API-токены. Пароли и ключи в GitHub не помещать. Сохранить `workers_dev: false`, `preview_urls: false` и настройки `assets`: публичный каталог и закрытые разделы используют основной домен.

5. Создать отдельный случайный ключ управляющего, сохранить его у владельца и записать его SHA-256 в секрет Worker `ADMIN_ACCESS_KEY_SHA256`. Если Worker ещё не существует, сначала выполнить публикацию из следующего пункта: до настройки секрета управление останется недоступным. После создания Worker:

   ```sh
   npx wrangler secret put ADMIN_ACCESS_KEY_SHA256 --config wrangler.json
   ```

   Ввести **SHA-256**, а в интерфейсе админки использовать исходный ключ. В репозитории ключа и его действующего хеша нет.

6. Установить зависимости и опубликовать:

   ```sh
   npm ci
   npm run check
   npm run test:auth
   npm run deploy
   ```

   Команда собирает Worker, проверяет заполнение настроек, применяет миграции к собственной D1 и загружает Worker с изображениями. Имена: Worker `trholod-uz`, база `trholod-db`, binding `DB`. Никакой учётной записи ChatGPT для работы этой версии не требуется.

7. Проверить `https://trholod.uz`: каталог и страницы товаров без входа, затем вход владельца в «Мои заказы» или управление, создание тестового заказа, изменение статуса и отмену с возвратом остатков. Проверить, что другой email и обращение без входа не получают доступ к `/admin`, `/orders`, `/api/admin` и `/api/orders`. Только после проверки считать перенос завершённым. Доступность страниц поисковым роботам не подтверждает их фактическое попадание в индекс поисковых систем.

`www.trholod.uz` пока не настроен. Для него настроить перенаправление на основной адрес либо отдельно добавить маршрут и такую же защиту закрытых путей Access.

## Обновления из GitHub

После первого успешного размещения в своём Cloudflare открыть Worker `trholod-uz` → Settings → Builds и подключить этот репозиторий. Выбрать ветку `main`, корневой каталог `/`, Node.js `22.23.2` (файл `.nvmrc`), команду сборки `npm run build`, команду размещения `npm run deploy:built`. Токен сборки должен иметь права на Workers и D1 нужного аккаунта. Не добавлять токен в файлы репозитория. Другие ветки не публиковать в рабочий Worker автоматически.

Секрет `ADMIN_ACCESS_KEY_SHA256` задаётся как runtime-secret Worker, а не как общедоступная переменная сборки. Проверять настройки сборки в Cloudflare после подключения: в самом репозитории нет действующей интеграции и нет сохранённых доступов к аккаунту.

## Локальная работа и проверки

Требуется Node.js 22.13+; проверено с 22.23.2.

```sh
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate:local
npm run check
npm run test:auth
npm run build
npm run start
```

Каталог, SEO-страницы и изображения работают без настройки Access. Закрытые разделы `/admin`, `/orders` и соответствующие API намеренно отвечают 503 без настроенного Access; с неправильным или отсутствующим подписанным токеном — 403. Локальной имитации владельца и скрытого обхода входа нет. Тесты авторизации используют временные RSA-ключи и подменяют получение открытых ключей только в отдельном тестовом процессе. Для интерактивной проверки заказов можно использовать отдельный тестовый Worker с защитой этих путей через Access в своём аккаунте.

`npm run dev` запускает Vite. Файлы `.dev.vars`, `.wrangler`, `node_modules`, `dist`, локальные базы и секреты исключены из Git. Две миграции схемы находятся в `drizzle/`; новые изменения создавать через `npm run db:generate`, не изменять уже применённые миграции.

## Авторизация и заказы

Worker самостоятельно проверяет JWT Cloudflare Access: подпись RS256, issuer, audience, срок действия, тип пользовательского токена и email владельца. Простые заголовки с email или старые заголовки Sites не дают доступа. Сбой получения ключей закрывает доступ к заказам и управлению, сохраняя доступность публичного каталога. Cloudflare Access защищает только `/admin`, `/orders`, `/api/admin`, `/api/orders` и их вложенные пути; дополнительная проверка в Worker не заменяет эту настройку. Все четыре пути должны входить в одно Access-приложение с единым AUD. Главная, каталог, карточки товаров, `/credits`, `/api/catalog`, изображения, `robots.txt` и `sitemap.xml` публичны.

Админка требует входа владельца и отдельного ключа. Ключ вводится в памяти страницы; после перезагрузки его нужно ввести снова. Повтор заказа не создаёт дубль. Отмена возвращает остаток один раз. Цена ноль означает «Цена по запросу» и исключает оплату/заказ этой позиции.

## Фотографии и оставшиеся правки каталога

Последнее требование владельца — **цветные одноразовые баллоны TR-GAS в фирменной упаковке как на образце**. Сейчас точно совпадает R134a. Остальные установленные фото баллонов/банки этому последнему требованию пока не соответствуют: нужны оригиналы поставщика для конкретных газов и фасовок. Эти изображения не перекрашивались и надписи не подделывались.

Для ряда GMCC/Panasonic/Toshiba показаны фотографии близкой модели или серии; подписи это поясняют. Две позиции Panasonic используют одно фото серии. Нельзя считать все фотографии точными изображениями каждой модели. Цены ряда позиций — ориентиры по внешним магазинам, а не утверждённый владельцем прайс.

Источники, точность соответствия моделей и цены описаны в `lib/originals-provenance.json`, `lib/catalog-provenance.json` и на странице `/credits`. Сохранены водяные знаки и исходная атрибуция. Наличие фото в репозитории не означает передачу лицензии на него; права производителей и поставщиков сохраняются. Общая открытая лицензия на сторонние изображения не заявлена. Неиспользуемые прежние вымышленные изображения исключены из этого экспорта.

## Уведомление поисковых систем после публикации

После запуска `https://trholod.uz` выполните `npm run indexnow:check` для проверки доступности файла подтверждения и sitemap, затем `npm run indexnow:submit` для ручной отправки публичных адресов в [IndexNow](https://www.indexnow.org/documentation). Скрипт читает действующий `sitemap.xml` (сейчас ожидаются 73 адреса), исключает закрытые разделы, API, посторонние домены и неканонические URL. Пока домен не работает, отправка останавливается. Публичный файл подтверждения — `public/fa7ea336dbe39a88a80b3a838bce7dd9.txt`; это не пароль и не доступ к хостингу. Автоматической или регулярной отправки нет.

Ответ IndexNow 200/202 означает получение уведомления сервисом, а не включение страниц в поиск. Уведомления распространяются между участвующими поисковиками, включая Bing; Google через IndexNow не уведомляется. Для Google в аккаунте с подтверждённым доступом к `trholod.uz` нужно вручную добавить `https://trholod.uz/sitemap.xml` в раздел Sitemaps [Google Search Console](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap#addsitemap). Сроки и факт индексации определяют поисковые системы; текущая индексация не подтверждена.
